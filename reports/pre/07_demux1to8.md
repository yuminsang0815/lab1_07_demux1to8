# 실험 전 레포트: 1:8 디멀티플렉서

작성일 2026-09-19.

## 목적과 예상값

1비트 데이터 입력 `i`를 3비트 선택선 `s[2:0]`이 지정하는 8비트 출력선 `o[7:0]` 중 하나로 전달하고 나머지는 0으로 유지합니다. top은 `demux_1x8`입니다. `i=0`이면 출력은 항상 0이며, `i=1`일 때 s의 값에 따라 활성 비트가 이동합니다.

| i | s[2:0] | o[7:0] (2진) | o[7:0] (16진) | 비고 |
|---:|---|---|---|---|
| 0 | 임의 (000~111) | 00000000 | 8'h00 | 입력 비활성화 시 전체 0 |
| 1 | 000 | 10000000 | 8'h80 | 최상위 비트(o[7])로 전달 |
| 1 | 011 | 00010000 | 8'h10 | 중간 비트(o[4])로 전달 |
| 1 | 111 | 00000001 | 8'h01 | 최하위 비트(o[0])로 전달 |

## 환경과 입력 파일

Windows, Git 2.55.0, VS Code 1.136.1, XSim 2026.1을 사용했습니다. 공개 템플릿의 커밋 `740aef5`를 공백이 있는 별도 폴더에 새로 clone했습니다. `LAB1.code-workspace`는 `vivado_2026_1/07_demux1to8`를 PROJECT, `common`을 COMMON으로 연결합니다.

[RTL](../../src/demux_1x8.v), [TB](../../sim/tb_demux_1x8.sv), [XDC](../../constraints/demux_1x8.xdc)를 사용했습니다. TB top은 `tb_demux_1x8`이며 16가지 입력 조합을 10ns 간격으로 총 160ns 동안 인가합니다. 삼항 조건 및 시프트 모델과 비교하여 16건 통과 시 PASS를 출력하고 160ns에 종료합니다.

## 실행과 관찰

VS Code 새 창에서 workspace를 열고 slang-server와 VaporView를 활성화했습니다. 저장 후 Terminal → Run Task...의 Check tools, Simulate를 실행하고 Open waveform으로 VCD를 열었습니다. `i,s,o`를 추가하고 Zoom to Fit와 ns 단위를 선택했습니다.

실제 [VS Code 작업 실행 로그](../../evidence/07/vscode/simulation.txt)에서 `LAB1_PASS demux_1x8 cases=16`과 160ns 종료를 확인했습니다.

| 구간(ns) | i | s | o[7:0] (hex) | 해석 |
|---|---|---|---|---|
| 0–80 | 0 | 000~111 | 00 | i=0 구간 전체에서 출력 0 유지 |
| 80–90 | 1 | 000 | 80 | s=000: o[7] 활성화 |
| 110–120 | 1 | 011 | 10 | s=011: o[4] 활성화 |
| 150–160 | 1 | 111 | 01 | s=111: o[0] 활성화 |

전환 순간 대신 구간 중간에서 커서를 읽었습니다. 파형만 눈으로 맞아 보이는 것에 더해 자동 비교 16건과 정상 종료를 함께 확인했습니다.

## 보드 실험 계획

KEY1(i)=K4, DIP1~3(s[2:0]), LED1~8(o[7:0]), LVCMOS33입니다. Vivado에서 같은 TB를 실행한 다음 bit를 생성하고 보드에 다운로드합니다. KEY1을 누르지 않았을 때 모든 LED가 소등되는지 확인하고, KEY1을 누른 상태에서 스위치 조작에 따라 LED1부터 LED8까지 순차 점등되는 이동 현상을 사진·영상에 담을 계획입니다.
